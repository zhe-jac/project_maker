# LESSONS — cross-project

Learned across all projects. Read at the start of every cycle. The retro adds to this;
prune entries that stop being true. Seeded with starting heuristics.

## Planning
- Build the walking skeleton (ugly, end to end) before any feature gets depth.
- Define interfaces/contracts in the first task so parallel tasks don't collide.
- Tasks bigger than ~90 min of agent work get split — they fail review more often.

## Build
- Verify third-party API usage against current docs; model memory of APIs goes stale.
- Seed realistic demo data early; lorem ipsum hides UX problems.

## Review
- A review without evidence (file:line, command output, link) is not actionable — re-run it.
- Reviewers that never block are not reviewing; check score distributions in retro.

## Hackathons
- Sponsor-track prizes usually have far fewer serious entrants than the overall prize.
- The wow moment belongs in the first 45 seconds of the demo.
- Judges reward a narrow thing that works over a broad thing that half works.
